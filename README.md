# 💈 Barbershop Bot

Telegram-бот для барбершопа: онлайн-запись клиентов и админ-панель прямо в чате.

**Стек:** Python 3.12 · aiogram 3 · PostgreSQL 16 · SQLAlchemy 2 (async) · Alembic · APScheduler · Docker.
**Языки клиентской части:** русский, română, English.

## Возможности

**Клиент**
- Три языка: русский, румынский, английский. Язык берётся из профиля Telegram и меняется кнопкой «🌐 Язык» или командой `/language`.
- Запись в 4 шага: услуга → барбер → дата → время → подтверждение.
- Просмотр активных записей, перенос и отмена.
- Услуги с ценами и длительностью, список барберов, контакты, график работы, FAQ.
- Автонапоминания за 24 часа и за 2 часа до визита.

**Администратор** (доступ по `ADMIN_ID`)
- Услуги: создание, редактирование названия/цены/длительности/описания, скрытие, удаление.
- Барберы: создание, редактирование, скрытие, удаление.
- График: рабочие часы по дням недели, выходные, исключения (на конкретную дату — для одного барбера или для всего барбершопа).
- Записи: список предстоящих, карточка записи, отмена и перенос с уведомлением клиента.
- Клиенты: список с количеством записей.
- Статистика: записи, клиенты, популярные услуги, барберы, выручка за день и месяц.
- Экспорт записей в CSV (за 7 / 30 / 90 дней или за всё время).
- Отметка «клиент не пришёл» (`no_show`) — слот закрывается, напоминания снимаются.
- Уведомления администраторам о новых, перенесённых и отменённых записях — на языке барбершопа.

## 1. Быстрый старт в Docker

```bash
cp .env.example .env
# заполните BOT_TOKEN и ADMIN_ID
docker compose up --build
```

При старте контейнера автоматически применяются миграции (`alembic upgrade head`).
Чтобы дополнительно залить демо-данные (4 услуги, 2 барбера, график Пн–Сб), поставьте в `.env`:

```env
SEED_ON_START=true
```

Остановка: `docker compose down` (данные сохраняются в volume `pgdata`), полная очистка: `docker compose down -v`.

## 2. Переменные окружения

Минимально необходимые:

| Переменная | Пример | Описание |
|---|---|---|
| `BOT_TOKEN` | `123456:AA...` | Токен от [@BotFather](https://t.me/BotFather) |
| `DATABASE_URL` | `postgresql+asyncpg://barber:barber@localhost:5432/barbershop` | DSN PostgreSQL (схема приводится к `postgresql+asyncpg` автоматически) |
| `ADMIN_ID` | `123456789` или `123456789,987654321` | Telegram ID администраторов через запятую |
| `TIMEZONE` | `Europe/Chisinau` | Часовой пояс барбершопа |
| `DEFAULT_LANGUAGE` | `ru` | Язык по умолчанию: `ru`, `ro` или `en` |
| `DEFAULT_CURRENCY` | `MDL` | Валюта новых услуг |

Необязательные (значения по умолчанию — в `.env.example`): `LOG_LEVEL`, `SQL_ECHO`, `SLOT_STEP_MINUTES`, `BOOKING_HORIZON_DAYS`, `MIN_LEAD_MINUTES`, `CANCEL_MIN_LEAD_MINUTES`, `MAX_ACTIVE_APPOINTMENTS`, `REQUIRE_PHONE`, `THROTTLE_INTERVAL`, `THROTTLE_BURST`, `SEED_ON_START`, `SHOP_NAME`, `SHOP_ADDRESS`, `SHOP_PHONE`, `SHOP_MAPS_URL`.

Секреты хранятся только в `.env` — файл в `.gitignore`, а логи маскируют токены и пароли в DSN.

## 3. Запуск без Docker

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

cp .env.example .env      # заполните BOT_TOKEN, ADMIN_ID, DATABASE_URL
alembic upgrade head
python -m app.seed        # необязательно: демо-услуги и барберы
python -m app.main
```

Нужен работающий PostgreSQL 15+ (расширение `btree_gist` создаётся миграцией автоматически).

## 4. Миграции

```bash
alembic upgrade head                          # применить все
alembic downgrade -1                          # откатить последнюю
alembic revision --autogenerate -m "описание" # создать новую после правки моделей
alembic current                               # текущая ревизия
```

`env.py` берёт URL из настроек приложения и работает через async-движок, поэтому отдельный синхронный драйвер не нужен.

## 5. Как назначить администратора

1. Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш `id`.
2. Впишите его в `.env`: `ADMIN_ID=123456789` (несколько — через запятую).
3. Перезапустите бота и отправьте `/admin`.

Проверка прав выполняется фильтром на уровне админ-роутера, поэтому все админ-хендлеры и кнопки закрыты для остальных пользователей.

Демо-клиент проходит весь сценарий: `/start` → услуга → барбер → дата → время → подтверждение → «Мои записи», а затем показывает админ-панель. Та же переменная `TELEGRAM_API_BASE` пригодится, если вы поднимаете [собственный Bot API server](https://core.telegram.org/bots/api#using-a-local-bot-api-server).

## 9. Языки и локализация

Клиентская часть переведена на русский, румынский и английский: меню, процесс записи, «Мои записи», услуги, контакты, FAQ, напоминания и тексты ошибок. Даты тоже локализованы — «15 сентября», «15 septembrie», «15 September».

Как это работает:

- при первом сообщении язык берётся из профиля Telegram (`ru-RU`, `ro-MD`, устаревший `mo` — всё распознаётся), иначе `DEFAULT_LANGUAGE`;
- клиент меняет язык кнопкой «🌐 Язык» или командой `/language`, выбор сохраняется в `users.language_code` и больше не перезаписывается настройкой его приложения;
- напоминания и уведомления о переносе/отмене приходят клиенту на его языке, а администратору — на `DEFAULT_LANGUAGE`.

**Добавить язык:** создайте `app/bot/i18n/locales/<код>.py` по образцу `en.py`, добавьте код в `LANGUAGES`, `LANGUAGE_NAMES` и `TRANSLATIONS` (`app/bot/i18n/__init__.py`), названия месяцев и дней — в `app/utils/dt.py`, код языка — в `SUPPORTED_LANGUAGES` (`app/config/settings.py`). Тесты в `tests/test_i18n.py` сами проверят, что наборы ключей и плейсхолдеры совпадают со всеми языками.

**Тексты админ-панели остаются русскими.** Это осознанное упрощение: панель видит только владелец, а клиентская часть — все гости. Ключи для перевода панели добавляются в те же словари.

## 10. Как добавить услугу или барбера

Через бота: `/admin` → «💇 Услуги» → «➕ Добавить» (название → длительность → цена → описание).
Барберы: `/admin` → «👨‍💈 Барберы» → «➕ Добавить», затем `/admin` → «🕐 График работы» → выбрать барбера → задать часы по дням недели.

Через код: правьте списки `DEFAULT_SERVICES` / `DEFAULT_BARBERS` / `DEFAULT_WEEK` в `app/seed.py` и запустите `python -m app.seed` (скрипт идемпотентен).

Удаление барбера или услуги блокируется, если по ним есть активные записи, — вместо этого используйте «Скрыть»: карточка исчезнет из выбора, а история сохранится.

## 11. Как это устроено

**Время.** В базе всё хранится в UTC (`timestamptz`), пользователю показывается локальное время `TIMEZONE`. Переходы на летнее/зимнее время учитываются через `zoneinfo`.

**Защита от двойной записи — три уровня:**
1. клиенту показываются только свободные слоты;
2. создание записи идёт под `pg_advisory_xact_lock` по барберу с повторной проверкой слота внутри транзакции;
3. в PostgreSQL стоит `EXCLUDE USING gist` — пересечение подтверждённых записей одного барбера невозможно физически.

**Слоты** считаются в чистой функции `app/services/slots.py` с учётом графика барбера, длительности услуги, занятых интервалов, выходных, исключений и текущего времени (`MIN_LEAD_MINUTES`).

**Напоминания** создаются вместе с записью, хранятся в таблице `notifications` с `UNIQUE(appointment_id, kind)` и отправляются планировщиком раз в минуту — повторная отправка невозможна даже после перезапуска. При отмене или переносе неотправленные напоминания удаляются или пересоздаются.

**Надёжность.** Каждый апдейт обрабатывается в своей сессии с гарантированным rollback, повторные нажатия перехватываются (состояние очищается до записи в БД), ошибки Telegram API (`retry_after`, блокировка бота, сетевые сбои) обрабатываются отдельно, при `SIGINT`/`SIGTERM` бот корректно останавливает polling, планировщик и пул соединений.

## 12. Что сделано для защиты

- **Только личные чаты.** Апдейты из групп и каналов отбрасываются до обращения к базе: в общем чате карточки записей и телефоны клиентов видели бы все участники.
- **Права администратора** проверяются фильтром на админ-роутере — он закрывает и все вложенные роутеры, и команды, и кнопки. Пустой `ADMIN_ID` не делает админом никого.
- **Чужие записи недоступны**: владелец проверяется и в хендлере, и в сервисе, поэтому подделанный UUID в `callback_data` ничего не даст.
- **Экранирование HTML** для всех пользовательских строк: имя клиента вида `<a href="…">` не превратится в ссылку в сообщении администратору.
- **Экспорт CSV** нейтрализует формулы (`=`, `+`, `-`, `@`) — имя в профиле Telegram не станет кодом в Excel.
- **Валидация ввода**: длина, диапазоны, кратность, `NaN`/`Infinity` в цене, не-десятичные «цифры», даты только в пределах горизонта.
- **Лимиты Telegram** соблюдаются на исходящих запросах: длинный список обрезается вместе с корректным закрытием HTML-тегов.
- **Флуд**: token bucket на пользователя с обратной связью, чтобы кнопка не «зависала».
- **Горизонт записи** проверяется на сервере, а не только в клавиатуре.
- **Секреты**: токен хранится как `SecretStr`, логи маскируют токены и пароли в DSN.
- **Таймауты БД**: `statement_timeout` 15 с, `idle_in_transaction_session_timeout` 30 с, ограниченное ожидание advisory-lock — зависшая транзакция не съест пул соединений.

## Бэкапы

Единственное, чего нельзя восстановить после сбоя, — база записей и клиентов. В комплекте есть скрипт:

```bash
./tools/backup.sh          # дамп в ./backups, ротация 14 копий
```

Добавьте в cron и **проверьте восстановление** хотя бы один раз:

```
30 3 * * * /path/to/barbershop_bot/tools/backup.sh >> /var/log/barbershop-backup.log 2>&1
```

Скрипт проверяет целостность gzip и отказывается считать успехом подозрительно маленький дамп. Команда восстановления печатается после каждого запуска. Порт PostgreSQL в `docker-compose.yml` слушает только `127.0.0.1` — база не торчит в интернет.

## Производительность

Замерено на PostgreSQL 16 (счётчики SQL-запросов зафиксированы тестами):

| Операция | Запросов |
|---|---|
| Свободные даты на 14 дней | 3 (один пакет, без запроса на каждый день) |
| Слоты одного дня | 3 |
| Создание записи | 7 (оба напоминания — одним `INSERT`) |
| Статистика админки | 4 (агрегаты с `FILTER` вместо восьми `SELECT`) |
| Списки записей и клиентов, экспорт | по 1 (без N+1) |

Нагрузочная проверка: 60 одновременных попыток записи обрабатываются примерно за 1,5–2 с, пересечений в базе — ноль.

## Принятые допущения

- Все барберы оказывают все услуги (отдельной привязки услуг к мастерам нет), цена привязана к услуге, а не к паре «услуга + мастер».
- Один слот — один клиент; параллельных кресел у мастера нет.
- Валюта по умолчанию MDL, хранится в записи вместе с ценой на момент бронирования, поэтому изменение прайса не меняет историю.
- Записи создаются не позднее чем за `MIN_LEAD_MINUTES` (60 мин) до начала, отмена и перенос — не позднее чем за `CANCEL_MIN_LEAD_MINUTES` (120 мин).
- Горизонт записи — `BOOKING_HORIZON_DAYS` (14 дней), одновременно активных записей у клиента — до `MAX_ACTIVE_APPOINTMENTS` (3).
